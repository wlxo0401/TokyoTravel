不需要建置工具、部署在 GitHub Pages 上的靜態旅行計畫 Web 應用。
**以它為起點，和 AI 一起打造屬於你自己的旅行計畫範本。**

> 這個儲存庫只是一個**範例**。資料是照 2026 年 9 月的東京行程填好的，
> 但沒有任何硬性規定。喜歡就直接用；不喜歡就依自己的喜好改寫目的地、結構、
> 設計與功能，做出更好的範本。我們只是一個起點。

## 為什麼做這個

它源於一個觀察：**出發前你會認真做計畫，但旅途中不會重寫計畫。**
旅行從來不會 100% 照計畫進行，總有變數——但你不會在旅途中坐下來重做行程。
所以這個應用把「做計畫」分成兩個階段。

- **出發前 — 規劃**：和 AI 一起排行程，提前把需要的資訊（地點、連結、候選）放進去。
  推送到 GitHub 就上線，把連結分享給同行的人即可。
- **旅途中 — 參考（唯讀）**：這時你不編輯計畫。它只是用來
  **查看你準備好的資訊，並在現場快速決定。**
  - 用日期分頁一眼看清當天動線
  - 只看每個區域的候選地點鬆散清單，現場再選（不是時刻表）
  - 一鍵地圖導航（韓國境內用 Naver，日本境內用 Google）
  - 去過的地方打勾（儲存在本機裝置上）

計畫不是強制的。與其排死時刻表，不如保留一個寬鬆的順序和一份候選清單，邊走邊選。
這就是旅行。

## 亮點

- 無框架、無打包工具、無後端。純 HTML/CSS/ES 模組。
- 資料與介面分離——所有旅行資訊都在一個 `data/trip.js` 裡。
- 固定淺色模式，行動裝置優先（桌機也能用）。

## 快速開始

### 1. 複製並在本機執行

```bash
git clone https://github.com/<your-name>/<your-repo>.git
cd <your-repo>
python3 -m http.server 8000
# http://localhost:8000
```

直接在瀏覽器開啟 `index.html` 會導致 ES 模組無法載入，所以務必用本機伺服器提供。
（也可以用任意靜態伺服器，如用 `npx serve` 取代 `python3`）

### 2. 改成你的旅行

最快的方式是**交給 AI**。打開整個儲存庫，然後說
「把這個專案改成我去 ○○ 的旅行」——它會從 `data/trip.js` 開始，
必要時連同版面、分頁結構和樣式一起調整。

本儲存庫給 AI 的工作規則放在 [`CLAUDE.md`](CLAUDE.md) —— Claude Code 會自動讀取；
其他工具請指向這個檔案作為規則。

### 3. 部署（GitHub Pages）

1. 儲存庫 → **Settings → Pages**
2. **Source: Deploy from a branch**，Branch：`main` / `/(root)`
3. 幾分鐘後在 `https://<your-name>.github.io/<your-repo>/` 上線
4. 把連結分享給同行的人。之後只要推送變更就會自動更新。

`.nojekyll` 檔案會略過 Jekyll 處理。所有資源路徑都是相對路徑，因此在子路徑部署下也能正常運作。

## 注意

> [!WARNING]
> **不要直接填入訂位代號或個人資訊。** `data/trip.js` 會提交到儲存庫並透過 GitHub Pages
> 公開發布，即使之後刪除也會留在 git 歷史裡。請不要放入訂位代號、護照／證件號碼、電話
> 號碼、完整住址、門鎖密碼等資訊，這些請透過私密管道與同行的人分享。地點名稱、大致
> 區域和地圖座標則沒問題。
