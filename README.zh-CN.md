无需构建工具、部署在 GitHub Pages 上的静态旅行计划 Web 应用。
**以它为起点，和 AI 一起打造属于你自己的旅行计划模板。**

> 这个仓库只是一个**示例**。数据是按 2026 年 9 月的东京之行填好的，
> 但没有任何硬性规定。喜欢就直接用；不喜欢就按自己的口味改写目的地、结构、
> 设计和功能，做出更好的模板。我们只是一个起点。

## 为什么做这个

它源于一个观察：**出发前你会认真做计划，但旅途中不会重写计划。**
旅行从来不会 100% 按计划进行，总有变数——但你不会在旅途中坐下来重做行程。
所以这个应用把「做计划」分成两个阶段。

- **出发前 — 计划**：和 AI 一起排行程，提前把需要的信息（地点、链接、候选）放进去。
  推送到 GitHub 就上线，把链接分享给同行的人即可。
- **旅途中 — 参考（只读）**：这时你不编辑计划。它只是用来
  **查看你准备好的信息，并在现场快速决定。**
  - 用日期标签一眼看清当天动线
  - 只看每个区域的候选地点松散清单，现场再选（不是时刻表）
  - 一键地图导航（韩国境内用 Naver，日本境内用 Google）
  - 去过的地方打勾（保存在本机设备上）

计划不是强制的。与其排死时刻表，不如保留一个宽松的顺序和一份候选清单，边走边选。
这就是旅行。

## 亮点

- 无框架、无打包工具、无后端。纯 HTML/CSS/ES 模块。
- 数据与界面分离——所有旅行信息都在一个 `data/trip.js` 里。
- 固定浅色模式，移动端优先（桌面端也能用）。

## 快速开始

### 1. 克隆并本地运行

```bash
git clone https://github.com/<your-name>/<your-repo>.git
cd <your-repo>
python3 -m http.server 8000
# http://localhost:8000
```

直接在浏览器打开 `index.html` 会导致 ES 模块无法加载，所以务必用本地服务器提供。
（也可以用任意静态服务器，如用 `npx serve` 代替 `python3`）

### 2. 改成你的旅行

最快的方式是**交给 AI**。打开整个仓库，然后说
「把这个项目改成我去 ○○ 的旅行」——它会从 `data/trip.js` 开始，
必要时连同布局、标签结构和样式一起调整。

本仓库面向 AI 的工作规则在 [`CLAUDE.md`](CLAUDE.md) 中 —— Claude Code 会自动读取；
其他工具请指向这个文件作为规则。

### 3. 部署（GitHub Pages）

1. 仓库 → **Settings → Pages**
2. **Source: Deploy from a branch**，Branch：`main` / `/(root)`
3. 几分钟后在 `https://<your-name>.github.io/<your-repo>/` 上线
4. 把链接分享给同行的人。之后只要推送改动就会自动更新。

`.nojekyll` 文件会跳过 Jekyll 处理。所有资源路径都是相对路径，因此在子路径部署下也能正常工作。

## 注意

> [!WARNING]
> **不要直接填入预订号或个人信息。** `data/trip.js` 会提交到仓库并通过 GitHub Pages
> 公开发布，即使之后删除也会留在 git 历史里。请不要放入预订号、护照／证件号、电话号码、
> 完整住址、门锁密码等信息，这些请通过私密渠道与同行的人分享。地点名称、大致区域和
> 地图坐标是可以的。
